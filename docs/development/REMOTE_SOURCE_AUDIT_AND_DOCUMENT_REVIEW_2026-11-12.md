## 3. 核验发现

### 3.1 主程序当前功能边界

远程 `src/main.cpp`：

- 使用 `DHTSensor` 封装类；
- 在 `systemInit()` 中调用 `dhtSensor.begin(DHT_SENSOR_PIN)`；
- 通过约 2000 ms 的日志周期调用状态输出；
- 使用 `dhtSensor.readAll(temperature, humidity)` 读取温湿度；
- 当前文件尚未实现风扇控制、Wi-Fi 通信或 AI 决策。

因此，项目文档不得将上述尚未实现的功能写成已完成。

### 3.2 DHT 驱动初始化

远程 `src/sensors/dht_sensor.cpp` 中，`begin()` 创建 DHT 对象后调用：

```cpp
_dhtInstance = new DHT(_pin, _type, 6);
_dhtInstance->begin(55);
```

核验时确认远程源码包含 `_dhtInstance->begin(55);`。

技术说明：

- `begin(55)` 是当前 Adafruit DHT 库 API 的初始化调用；
- 55 微秒是该库接口的参数值，不应表述为 DHT11 专属的通用标准；
- 封装类的缓存时间变量与 Adafruit 库内部读取时间变量是不同状态，文档分析时不能混为一谈。

### 3.3 首次读取的时间边界

当前封装类的初始状态包括：

- `_lastReadTime = 0`
- `_cacheValid = false`

如果封装类在系统启动后不足 2000 ms 就首次调用读取函数，且代码进入缓存时间间隔分支，则缓存尚未有效，读取可能返回失败。

但当前主程序的状态输出周期约为 2000 ms，不能据此断言当前主程序必然在启动后首次读取失败。文档应准确描述条件边界，而不是把条件性风险写成必现故障。

### 3.4 独立测试程序与主程序调用路径

远程 `src/test_dht11_main.cpp` 的测试读取路径与主程序封装路径并不完全相同。独立测试程序会调用 DHT 库的 `read(true)`，再读取温度和湿度。

因此，独立测试成功可以证明该测试程序在当时条件下能读取传感器，但不能单独证明主程序封装层的所有调用时序和缓存行为等效。

### 3.5 PlatformIO 配置

远程 `platformio.ini` 核验结果：

- 主环境使用 `platform = espressif32`、`board = esp32-s3-devkitc-1`、`framework = arduino`；
- 依赖声明包含 Adafruit DHT sensor library 和 Adafruit Unified Sensor；
- 主程序的 `build_src_filter` 包含主程序及 sensors、ai、communication、control 目录；
- 独立 DHT 测试环境仅编译 `test_dht11_main.cpp`；
- 测试串口配置为 COM5。

注意：`esp32-s3-devkitc-1` 是当前 PlatformIO 配置中的编译目标，不应据此声称它与实物 YD-ESP32-S3 开发板的全部硬件参数完全一致。依赖项中的版本范围也不等同于精确锁定的实际安装版本。
