## 1. 实验目标

为 SmartFan 2.0 建立 Flask 后端风扇控制指令队列，为后续 ESP32 主动轮询、执行指令、返回 ACK，以及网页显示执行状态提供服务端基础。

预期链路：

网页创建控制请求 → Flask 生成并管理指令 → ESP32 获取指令 → ESP32 执行 → ESP32 返回 ACK → Flask 更新指令状态 → 前端查询状态。

本阶段仅完成后端指令队列，不代表 ESP32 已能实际接收指令或控制风扇。

## 2. 实施过程

1. 根据现有 Flask 后端结构，在 `backend/app.py` 中实现指令队列数据结构及相关 API 路由。
2. 为每条控制指令生成唯一 `command_id`，用于后续查询、执行确认和去重。
3. 建立指令生命周期状态管理。
4. 增加 AUTO / MANUAL 控制模式管理。
5. 对风扇档位进行 0–5 范围校验。
6. 设置指令有效期为 5 分钟，并处理过期指令。
7. 增加重复 ACK 处理及线程安全保护。
8. 新增自动化测试文件，并生成测试结果文件和交付报告。

## 6. 当前限制与未完成事项

1. ESP32 端指令轮询尚未完成。
2. ESP32 执行指令后的 ACK 实际通信尚未完成。
3. 前端模式切换 UI、指令状态通知及状态轮询尚未完成。
4. AUTO / MANUAL 在 ESP32 本地控制逻辑中的完整同步与隔离尚未完成。
5. 需要确认指令队列的实际存储方式。如果当前为内存队列，Flask 进程重启会导致队列数据丢失；数据库持久化属于后续工作，不能将当前实现描述为持久化队列。
6. 本阶段没有完成 ESP32 实机控制验收，不能据此认定网页已经能够改变风扇转速。
