## 1. 修复背景

此前针对固件进行只读审查，识别出以下问题：

| 缺陷编号 | 问题 | 风险 / 影响 |
|---|---|---|
| DEF-001 | LEDC PWM 初始化与写入结果缺少正确的失败检查；此前尝试使用 `ledcRead()` 的返回值判断初始化失败，判断方式不正确 | PWM 外设初始化失败时，程序可能错误地认为风扇控制器可用 |
| DEF-003 | HTTP POST / GET 设置了连接超时，但缺少响应读取超时设置 | 同步 HTTP 请求等待网络响应时，可能延长主循环阻塞时间，影响 PIR 与风扇状态机的及时更新 |

DEF-002（主循环中的 `delay(10)`）经审查认为位于 PIR 读取和 PWM 更新之后，本轮不作为需要修复的缺陷。

## 2. DEF-001 返修内容

据 Qwen 提供的返修摘要，修改如下：

1. 删除通过 `ledcRead()` 返回值小于零来判断初始化失败的逻辑。该函数返回的是当前 PWM 占空比读数，不应作为 `ledcAttach()` 是否成功的判据。
2. 在 `fan_controller.cpp` 中检查 `ledcAttach()` 的布尔返回值；失败时将 `_initialized` 置为 false，输出错误日志并返回失败。
3. 检查 `ledcWrite()` 的布尔返回值；写入失败时输出错误日志，并使初始化/控制状态进入失败保护。
4. 在风扇控制器相关控制函数中保留 `if (!_initialized) return;` 保护，避免初始化失败后继续执行 PWM 控制操作。
5. 在 `main.cpp` 中，当 `fanController.begin()` 返回 false 时输出初始化失败日志。

## 3. DEF-003 返修内容

据 Qwen 提供的返修摘要，`wifi_manager.cpp` 中的 `_sendHTTPPost()` 与 `_sendHTTPGet()` 均增加：

- `http.setConnectTimeout(HTTP_TIMEOUT)`：设置连接阶段超时；
- `http.setTimeout(HTTP_TIMEOUT)`：设置 HTTP 响应读取等待超时；
- `HTTP_TIMEOUT` 当前配置为 5 秒。

### 3.1 影响与限制

这补充了连接和响应读取阶段的超时设置，但不能简单解释为“整个 HTTP 请求的绝对总耗时最多 5 秒”。同步 HTTP 调用仍可能占用主循环一段时间；需要通过实际网络测试观察 PIR 事件处理、PWM 更新和请求失败恢复情况。
