# EXP-004：ESP32-S3 Wi-Fi 连接与 Flask HTTP 数据上传验证

- 实验编号：EXP-004
- 实验日期：2026-11-19（依据本次终端日志日期；此前过程为历史操作回顾）
- 实验名称：ESP32-S3 通过 Windows 移动热点向 Flask 后端上传传感器数据
- 状态：completed（ESP32 → Flask 的 HTTP 上传已验证）；长期稳定性与断线重连仍待验证
- 记录性质：根据本次对话中用户实际提供的终端输出整理。未收到原始截图、完整串口日志文件或屏幕录像，因此本记录不将其描述为已归档的独立附件。
- 关联模块：ESP32-S3 firmware / Wi-Fi / HTTP / Flask backend

## 1. 实验目的

验证 ESP32-S3 能否通过与电脑处于同一局域网的 Wi-Fi 网络，将温度、湿度数据发送到运行在 Windows 电脑上的 Flask 后端，并由后端成功接收。

本次验证范围仅包括 ESP32 到 Flask 的数据上传链路，不代表后端到 ESP32 的命令下发、风扇驱动或自动控制已完成。

## 2. 网络拓扑与地址记录

本次采用 Windows 移动热点作为 ESP32 与电脑之间的局域网连接方式。

| 设备 / 接口 | 实际记录的地址 | 用途 / 说明 |
|---|---|---|
| Windows 移动热点网关（本地连接* 2） | 192.168.137.1 | ESP32 访问电脑 Flask 服务时使用的局域网网关地址 |
| ESP32 | 192.168.137.171 | 后端访问日志中观察到的客户端地址 |
| 电脑 WLAN 接口 | 10.100.7.228 | 电脑另一个 WLAN 接口地址；不能与移动热点网关地址混为一谈 |
| Flask 服务端口 | TCP 5000 | 后端 HTTP 服务端口 |

说明：以上地址来自此前用户提供的 Windows 网络配置和 Flask 日志。DHCP 分配地址可能随网络环境变化；重新测试时应重新检查实际地址，不应将这些地址视为永久固定地址。

## 3. 实验环境

- 主控：ESP32-S3 开发板（项目中已识别为 YD-ESP32-S3 Classic V1.0）。
- 网络：Windows 移动热点。
- 后端：Windows 电脑运行 Python Flask。
- 后端监听：0.0.0.0:5000。
- 数据接收接口：POST /api/sensor/data。
- 本次日志中的数据字段：temperature、humidity、gear。
- Wi-Fi 密码、令牌等敏感信息不写入仓库。

## 4. 操作过程与排查记录

### 4.1 确认电脑网络接口

此前通过 Windows `ipconfig` 检查网络接口，记录到：
- WLAN：10.100.7.228。
- Windows 移动热点对应的“本地连接* 2”：192.168.137.1。

因此，ESP32 连接移动热点后，访问电脑上 Flask 服务应使用移动热点所在局域网的电脑地址，而不是不加区分地使用电脑其他网络接口地址。

### 4.2 检查后端端口

曾执行：

```powershell
Test-NetConnection 192.168.137.1 -Port 5000
```

在 Flask 尚未启动时，TCP 测试失败。这一结果说明当时服务端口没有可用监听服务，不能据此认定 ESP32 Wi-Fi 配置错误。

### 4.3 启动 Flask 服务

在项目后端目录启动：

```powershell
cd E:\PlatformIOProjects\SmartFan2\backend
.\.venv\Scripts\python.exe app.py
```

此前启动日志显示 Flask 监听：
- http://127.0.0.1:5000
- http://10.100.7.228:5000
- all addresses（0.0.0.0）

注意：本次 2026-11-19 的启动输出再次确认服务监听 0.0.0.0:5000，且 Werkzeug 显示调试模式开启。该开发服务器适合当前本地开发验证，不应描述为生产部署配置。

### 4.4 观察 ESP32 上传结果

Flask 启动后，后端日志出现来自 ESP32 地址 192.168.137.171 的 POST 请求，并返回 HTTP 200。

此前一次实际日志：

```text
Sensor data received: temp=23.1°C, hum=51.0%, gear=-1
192.168.137.171 ... "POST /api/sensor/data HTTP/1.1" 200
```

2026-11-19 10:40:25 启动 Flask 后，日志再次出现：

```text
2026-11-19 10:40:25,639 - __main__ - INFO - Starting SmartFan 2.0 Backend Server...
2026-11-19 10:40:25,640 - __main__ - INFO - Server running on http://0.0.0.0:5000
2026-11-19 10:40:25,686 - werkzeug - WARNING - This is a development server. Do not use it in a production deployment.
2026-11-19 10:40:26,117 - werkzeug - WARNING - * Debugger is active!
2026-11-19 10:40:30,885 - __main__ - INFO - Sensor data received: temp=23.0°C, hum=51.0%, gear=-1
2026-11-19 10:40:30,887 - werkzeug - INFO - 192.168.137.171 - - [19/Nov/2026 10:40:30] "POST /api/sensor/data HTTP/1.1" 200 -
```

随后还观察到一次数据：
- 温度：23.0 °C
- 湿度：51.0 %
- gear：-1
- HTTP：200

HTTP 200 与后端的 “Sensor data received” 日志共同证明：该时刻 ESP32 的传感器数据已到达 Flask 的 `/api/sensor/data` 接口，后端成功处理了该请求。

| 检查项目 | 结果 | 证据 / 说明 |

## 6. 本次暴露的运行问题

2026-11-19 后续排查网页实时折线图时，用户观察到浏览器控制台报错：

```text
Failed to load resource: net::ERR_CONNECTION_REFUSED
app.js:180 Failed to refresh data: TypeError: Failed to fetch
    at fetchSystemStatus (app.js:188:28)
    at refreshData (app.js:168:30)
```

同时，PowerShell 请求 `http://127.0.0.1:5000/api/status` 时出现“无法连接到远程服务器”。重新启动 Flask 后，ESP32 再次向后端上传数据并获得 HTTP 200。

这表明：
1. ESP32 到 Flask 的上传链路在 Flask 服务运行时可以成功。
2. Flask 服务停止或不可访问时，浏览器无法获取 API 数据，实时界面会出现连接错误。
3. 这次错误不能归因于 Wi-Fi 密码错误，也不能据此认定 ESP32 上传链路失效。
4. 后端启动、前端请求地址和服务存活检查需要进一步整理成可重复启动流程。
