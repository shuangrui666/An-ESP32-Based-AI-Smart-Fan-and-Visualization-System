验证 ESP32-S3 能否通过 GPIO4 从 DHT11 读取有效温度和湿度；在独立测试程序通过后，修复并验证项目主程序中的 DHT11 初始化和读取。

成功判据：
1. 独立测试程序能够返回有效温度和湿度，且不出现读取失败。
2. 主程序能够连续输出有效温度和湿度，而不是持续输出 Read Failed 或 NaN。
3. 主程序固件能够成功编译并上传至 COM5 对应的 ESP32-S3 开发板。

本次不涉及：风扇接线、风扇驱动、PWM 调速、Wi-Fi、后端、AI 模型和网页仪表盘。

## 4. 实验过程与调试记录

### 4.1 独立硬件测试程序

独立测试固件编译成功并上传至 ESP32-S3。上传报告确认串口 COM5，芯片识别为 ESP32-S3 (QFN56) v0.2。

用户提供的独立测试程序第 22 次输出：

```text

[读取方式 1] 调用 read() 底层函数:
  read() 返回值: true (OK)

  湿度: 42.0 %
  数据验证: 温度✓ 有效, 湿度✓ 有效
  >>> 本次读取：成功

[读取方式 2] 直接调用 readTemperature()/readHumidity():

[故障诊断]
  ✓ 传感器工作正常
```

该统计是独立测试程序报告的结果，不应误写为主程序的 22 次测试统计。

### 4.2 主程序初次读取失败

此前主程序串口输出过：
- `[DHTSensor] Read failed, temperature=nan, humidity=nan`
- `[DHTSensor] Sensor read timeout or checksum error`
- `[DHT11] Temperature: Read Failed`
- `[DHT11] Humidity: Read Failed`

### 4.3 原因定位与代码修复

根据对独立测试程序和主程序的代码对比，发现主程序 `src/sensors/dht_sensor.cpp` 的 `begin()` 函数创建了 DHT 对象，但缺少对对象的初始化调用。

修复前：
```cpp
_dhtInstance = new DHT(_pin, _type, 6);
// 缺少 DHT 初始化调用
```

修复后：
```cpp
_dhtInstance = new DHT(_pin, _type, 6);
_dhtInstance->begin(55);
```

同时，`platformio.ini` 的主程序环境增加了 `build_src_filter`，用于排除独立测试源文件，避免测试代码与主程序一起编译时发生重复定义。具体过滤规则以仓库中的当前配置文件为准。

修改后 PlatformIO Build 成功，主程序固件上传至 COM5 成功。
