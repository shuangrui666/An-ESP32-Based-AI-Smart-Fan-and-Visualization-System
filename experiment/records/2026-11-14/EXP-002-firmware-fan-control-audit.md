## 4. 本次实际检查过程

### 4.1 检查风扇控制器的档位和 PWM 参数

读取 `src/control/fan_controller.cpp` 第 45–105 行，观察到：

- PWM 预设频率：5000 Hz。
- PWM 分辨率：8 bit。
- 预设占空比：20%、40%、60%、80%、100%。
- 代码定义了 OFF 和 GEAR_1 至 GEAR_5，即当前源码仍按 5 档组织。
- `begin(int pin = FAN_CONTROL_PIN)` 使用默认控制引脚宏。

**判断：** 这些参数只是代码配置和档位映射，不等于 PWM 已经初始化或实际输出。

### 4.2 查找风扇和 DHT11 引脚定义

通过 PowerShell 在 `src` 目录搜索 `FAN_CONTROL_PIN`，输出显示：

- `src/control/fan_controller.cpp` 第 40–41 行定义：
  `#ifndef FAN_CONTROL_PIN`
  `#define FAN_CONTROL_PIN 21  // 临时默认值，需根据实际情况修改`
- 第 168 行构造函数使用 `FAN_CONTROL_PIN`。

搜索 `DHT_SENSOR_PIN` 和 `DHT_SENSOR_TYPE`，输出显示：

- `src/sensors/dht_sensor.h` 第 31 行：`#define DHT_SENSOR_PIN 4`
- `src/sensors/dht_sensor.h` 第 34 行：`#define DHT_SENSOR_TYPE DHT11`
- `src/main.cpp` 第 112 行调用 `dhtSensor.begin(DHT_SENSOR_PIN)`。

**判断：**

- DHT11 使用 GPIO4，与此前实际接线记录一致。
- GPIO21 只是风扇控制器中的临时默认值，尚未经过开发板引脚可用性、其他外设占用及实际接线核实，不能据此直接接线。
- 在本次检索到的 `src` 文件中，未发现其他明确的 GPIO 数值配置；这不等于已经完成整个项目、开发板引脚复用和外部接线的全面核查。

### 4.3 检查风扇控制器的实际输出实现

读取 `src/control/fan_controller.cpp` 第 155–275 行，观察到：

- 第 176–200 行：`begin()` 将控制引脚设置为 OUTPUT，并将引脚拉低。
- 第 183–186 行：`ledcSetup()` 和 `ledcAttachPin()` 均处于注释状态，没有执行 PWM 初始化。
- 第 215–232 行：`setGear()` 计算档位对应的占空比，并调用 `setDutyCycle()`。
- 第 234–249 行：`setDutyCycle()` 仅保存占空比数值并调用 `_updatePWM()`。
- 第 251–263 行：`ledcWrite()` 处于注释状态；当前实际执行的是普通 `digitalWrite()`。
- 当占空比大于 0 时，GPIO 被设置为 HIGH；占空比为 0 时设置为 LOW。

**结论：** 当前这份控制器实现没有真正输出 PWM。任何非零占空比都会变成持续 HIGH，因此 20%、40%、60% 等数值不会产生对应的 PWM 占空比，也不能据此实现多档转速。当前代码不能用于证明风扇调速已实现。

### 4.4 检查主程序是否接入风扇控制器

读取 `src/main.cpp` 并搜索 `FanController`、`fanController`、`setGear`、`setPower`：

- 搜索没有返回匹配项。
- 主程序前 140 行显示全局实例包括 `DHTSensor dhtSensor` 和 `WifiManager wifiManager`，没有发现风扇控制器实例。
- `systemInit()` 初始化串口、DHT11 和 Wi-Fi。
- 主程序头部注释标记为 Phase 1 基础测试，注释中部分“不连接 DHT11”的描述与后续实际代码不一致，说明注释需要后续更新。
- 项目中没有找到 `src/control/fan_controller.h`。当前 `FanController` 类声明和实现可在 `fan_controller.cpp` 中看到；本次没有创建缺失的头文件。

**判断：** 当前主程序没有把风扇控制器接入系统初始化或运行流程。不能将独立存在的控制器源码视为已经集成到固件。

### 4.5 检查主循环和数据上传

读取 `src/main.cpp` 第 140–243 行，观察到：

- `uploadSensorData()` 先检查 Wi-Fi 连接，再读取 DHT11。
- 数据通过 `wifiManager.sendSensorData(temperature, humidity, -1)` 上传。
- 注释将 `-1` 说明为风扇尚未连接的暂定标记。
- `printSystemStatus()` 打印运行时间、堆内存、CPU 相关信息、芯片温度和 DHT11 读数。
- `setup()` 只调用 `systemInit()`。
- `loop()` 每 2 秒打印系统状态，每 5 秒上传一次传感器数据，每轮末尾延迟 100 ms。
- 本次读取的主程序片段中没有发现从后端接收风扇控制命令的处理流程。

**结论：** 当前主循环实现的是传感器监测与上传，并未形成后端到 ESP32 的风扇命令接收闭环。

- 本次没有改变 DHT11 的 GPIO4 接线。
- 本次没有将 USB 风扇接入 ESP32。
- 不允许将 USB 风扇直接接到 ESP32 GPIO。

- 在确认风扇电机/内部驱动类型、启动电流、驱动器额定值、保护措施、供电路径和 ESP32 可用 GPIO 前，不进行带电接线。
