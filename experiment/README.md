# 实验记录与证据管理

本目录用于保存 SmartFan 2.0 项目的实验计划、过程记录、原始证据、问题排查和测试结果，同时为课程项目要求提供可追溯的过程材料。记录应真实、及时、完整。

## 记录规则

1. 每次实验分配唯一编号，例如 EXP-001、EXP-002，编号一经使用不重复分配。
2. 实验开始前记录目的、设备、条件、风险检查、操作步骤和预先确定的成功判据；实验后补充真实现象、结果、问题及结论。
3. 过程记录应覆盖实验前、实验中和实验后。关键步骤应有照片、视频、串口日志、仪器读数或原始数据等证据；不适用时说明原因。
4. 失败实验、异常数据和被放弃的方案也要保留，注明原因，不得伪装成成功结果。
5. 照片、视频、串口日志和数据文件使用实验编号关联，例如 EXP-001-01.jpg、EXP-001-02.mp4。
6. 原始证据保留原文件，不覆盖、不只保留裁剪或标注版本。需要标注时另存副本，并说明处理方式。
7. 原始数据只追加、不覆盖；处理结果另存，并记录处理脚本、参数和输入文件。
8. 所有参数必须标明来源类别：实物标签、官方数据手册、商家说明、仪器实测或估算。未知内容写“待核实”，不可猜测。
9. 记录测量工具、量程/设置、单位、测量位置、实验条件和读数；没有仪器或无法测量时明确说明。
10. 模拟数据必须明确标记 SIMULATED，不得与真实实验数据混淆。
11. 每个重要结论应关联证据编号、文件路径或可信资料链接。芯片识别应保存清晰丝印照片和数据手册来源；成本报价应保存供应商、查询日期、数量区间和价格单位。
12. 每次重要修改都通过 Git commit 留下记录，提交说明应概括实际变更。
13. 不上传 Wi-Fi 密码、API Key、访问令牌、个人隐私或其他秘密信息。
14. 大型视频可留存在本地或经批准的存储位置；仓库中至少记录原始文件名、文件大小（如可得）、拍摄日期、内容说明、存放位置和访问方式。不要未经确认就提交超大文件。
15. 实验记录应在实验当天或尽快完成。若事后补记，必须标注“事后补记”、补记日期以及依据，不能伪装成实时记录。

## 每次实验的最低证据要求

- **实验前：** 实验目的、日期时间、设备清单、环境条件、风险检查、操作步骤和成功判据。
- **实验中：** 关键操作步骤、连接状态、原始读数、异常现象及对应照片/视频/日志。
- **实验后：** 实际结果、与成功判据对照、数据文件、问题分析、结论和后续行动。
- **证据索引：** 每个文件有唯一名称、类型、说明、原始/处理状态和存放路径。

## 实验文件命名

记录文件：records/YYYY-MM-DD/EXP-NNN-short-description.md

证据文件：EXP-NNN-序号-简短说明.扩展名

例如：
- records/2026-11-09/EXP-001-hardware-inventory.md
- EXP-001-01-all-components-original.jpg
- EXP-001-02-board-marking-original.jpg

日期必须使用实际实验日期，不要为了符合示例而填写未发生的日期。

## 实验状态定义

- planned：已计划，尚未执行。
- in_progress：正在执行。
- completed：按记录完成，证据已整理。
- failed：实验执行失败，保留失败证据。
- pending_verification：已有记录，但关键事实或证据仍待核实。

## 结论与更正要求

结论应区分“观察到的事实”“根据事实作出的解释”和“尚不能确定的事项”。样本不足、参数未确认或证据缺失时，明确写出限制。发现旧记录错误时，不静默覆盖：保留可追溯的更正说明、修改日期、修改原因和依据。
